## 4. SYSTEM MODULES & FUNCTIONAL SPECIFICATIONS

### MODULE 1: AUTHENTICATION & MULTI-TENANT ROLE MANAGEMENT
* **Dual Sign-In:** Implement a robust "Login with Google" OAuth2 workflow alongside a traditional Email/Password login.
* **Hash-Based Dynamic Routing:** For enhanced administrative security, access to administrative logins or roles must be dynamically hidden behind secure hashes or unique sub-paths generated by the Super Admin (e.g., `domain.com/admin/auth/{secure_role_hash}`).
* **Granular Permissions Matrix:** A full-scale Access Control List (ACL) system where the Super Admin can create custom roles (e.g., Match Scorer, Disciplinary Committee, Treasury Auditor, Team Manager) and check explicit permissions before routing or executing operations.

### MODULE 2: RUN-RATE CALCULATION ENGINE (CUSTOM CRICKET RULE)
* **The Problem:** Standard cricket decimalization evaluates an over out of 6 balls (e.g., 5.3 overs = 5.5 overs in normal fractions).
* **The Custom Formula:** The VCC rules explicitly calculate **1 individual ball as exactly 0.17 overs**.
    * *Example Calculation:* If 120 runs are chased in 5.3 overs:
        * Overs fraction = `5 + (3 * 0.17) = 5.51`
        * Net Run Rate (NRR) / Run Rate = `120 / 5.51 = 21.78`
* **Requirement:** Build a helper service/trait in Laravel to universally handle this calculation, rounding all final outputs strictly to two decimal places (e.g., `8.90`, `8.45`, `9.32`). This engine must feed directly into the Points Table generator.

### MODULE 3: THE LIVE REAL-TIME BALL-BY-BALL SCORING SYSTEM
* **The Scorer Interface:** A mobile-optimized, fast-response console interface for assigned "Scorers" to update matches live ball-by-ball.
* **Live Inputs:** Wicket (dropdown for types: bowled, caught, run-out, lbw), Runs (0, 1, 2, 3, 4, 6), Extras (Wide, No Ball, Bye, Leg Bye, Penalty), Bowler Select, Batter Strike Select.
* **Automated Triggers:** * Over completion checks.
    * Automatic calculation of individual batter strike rate and bowler economy.
    * Dynamic triggers for milestone trackers (Hat-tricks of wickets, Hat-tricks of sixes, 5 Sixes in a single over, 50s, 100s).
* **Persistence:** State must be safely cached (Redis or MySQL transaction logs) to prevent data loss on unexpected network disconnects inside remote village grounds.

### MODULE 4: TOURNAMENT & EDITION CONTROL CENTER
* **Edition Multi-Tenancy:** Ability to create Editions (e.g., "35th Edition"), assign a specific Host Village, upload primary edition branding/thumbnails, and set active/archived statuses.
* **The Tournament Hub:** The core consumer landing zone. Selecting an edition opens a sub-dashboard showing:
    * **Fixtures:** Interactive schedule tabs (Upcoming, Live, Completed).
    * **Points Table:** Dynamically calculated based on Match Results and the custom Run Rate Engine.
    * **Leaderboards:** Top 10 lists for Runs, Wickets, Boundaries, and MVPs.

### MODULE 5: GRANULAR STATISTICAL RECORD MANAGEMENT
* **Historical & Live Separation:** Ability for admins to manually input records or override them, alongside automated updates piped directly from the Live Scoring system.
* **Tracked Parameters:**
    * *Batting:* Total Runs, 50s, 100s, Hat-trick of Sixes, 5 Sixes in an Over, Strike Rate.
    * *Bowling:* Wickets, Maidens, Economy, Hat-trick of Wickets, 5-Wicket Hauls, Bowling Action Status (Flagged/Banned).
    * *Fielding & Keeping:* Catches, Run-outs, Stumpings.

### MODULE 6: COMPREHENSIVE DISCIPLINARY & FINANCE JOURNAL (VCC CABINET)
* **The Cabinet Portal:** A dedicated frontend showcase page featuring portraits, roles, and profiles of the executive VCC Cabinet members running the league.
* **Fine & Finance Ledger:** * Administrative dashboard to record incoming revenues: Tournament Entry Fees from the 16 villages, Sponsorship inputs.
    * Outgoing expenses: Official Fees (payments made to Umpires, Live Scorers, and Groundsmen).
    * **Player Fine System:** A public and internal disciplinary tracker where players are fined for code violations, with a clear status toggle (`Paid` / `Unpaid`). Players with active unpaid fines or "Banned" status indicators are automatically locked from being selected in the live scoring interface.

### MODULE 7: MATCH FIXTURING, SCHEDULES, & ENGAGEMENT POLLS
* **Schedule Builder:** Admin utility to pre-schedule matches, define pitches/grounds within the host village, and allocate official Umpires and Scorers.
* **Fan Engagement Polls:** Ability for admins to upload match/player prediction polls before a game starts (e.g., "Who will win the 35th Edition Opener?"). Users can cast anonymous or authenticated votes, displaying real-time responsive progress charts (SVG/CSS bar charts) inside the mobile view.
